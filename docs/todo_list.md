# 功能计划

- 主界面自定义创建多个窗口，log和终端; 
  - 多窗口，需要更多地支持键盘操作；
  - 默认只有一个窗口，可以通过选择某一个进行分裂，同时选择新窗口的类型(终端/监控/......);
- 同时监控多个文件，即，过滤条件应用到多个文件中；
  - 不只是日志文件，还可以监控特定文件；
- 日志界面支持类似Vim的操作；
  - 或者说整个工具都需要支持Vim，可以进行纯键盘操作；
- 监控某个进程的标准输出；
  - 例如本地调试Log捕获；
- 实现完整的终端；
- 导入文件夹，支持命令行打开，例如VSCode的 code .；
- 接入AI，做一个小型的“Agent”，进一步形成自动化Debug流？；
- 同时监控多个文件，所有文件内容，可以输出到同一个列表中；
  - 监控数据流在所有模块的行程；
- 对于终端来说，直接拖动文件到终端中，复制/移动此文件；
- 终端可以直接集成现有的Terminal https://github.com/alacritty/alacritty.git;
- AiAgent功能；
  - 管理多个Skill实体；
  - 辅助分析日志；
- "反向代理"，直接让agent能够直接通过管道在目标设备中执行安全命令，进行问题排查；
- 本地“外挂”脚本，比如检测目标机器指定文件状态，然后检测到某些log后就执行某些操作；
- 个性化设置，全部通过配置文件设置，界面上不提供任何可配置项；
  - 灵感来自kitty，以及减少界面上设计；
  - 配置选项，所有ssh连接，是否开启自动重连；
- 集成命令行 —— 打开日志文件，纯键盘搜索/过滤 —— 类似于nvim gerp;
- 组件 —— 串口状态；
